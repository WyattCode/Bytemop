0产品概览

一款透明、安全、可撤销的 Windows 磁盘清理与系统维护工具（Electron 桌面应用）。

定位
做“清理界的可信赖工具”：每一次删除都能说清楚删什么、为什么安全、怎么撤销。不靠恐吓式提示和捆绑推广赚钱。
目标用户
  • 普通用户：C 盘红了，想一键腾空间但怕删错
  • 进阶用户：想要明细、排除项、计划任务
  • 技术用户：想看规则、自己写规则
产品原则
  • 先预览，后删除
  • 默认可撤销（隔离区）
  • 最小权限，按需提权
  • 默认零遥测
  • 规则公开可审计
成功标准（北极星）
  • 单次清理释放空间
  • 清理后“误删投诉”≈0
  • 首次扫描 < 30 秒（SSD）
  • 从打开到完成清理 ≤ 3 次点击
明确不做
  • 注册表“清理”（收益低、风险高）
  • 内存“加速”、驱动更新
  • 常驻后台弹窗推广
  • 云端上传文件清单

1名词定义

全产品统一术语，界面、代码、规则文件都用同一套词。

术语定义
规则 Rule描述“在哪里找、哪些算垃圾、什么条件下能删”的一条声明式配置（见第 7 章）。一条规则对应界面上的一个勾选项。
规则包 Rule Pack一组规则的发布单位，如“系统”“浏览器”“开发者缓存”。带版本号与签名，可单独更新。
分类 Category界面上的分组：系统、浏览器、应用、开发者、隐私。
风险等级 Risk安全 删了只会重建，无副作用；谨慎 可能丢失登录态/历史，需明确提示；高级 可能影响功能，默认隐藏。
扫描 Scan只读操作：按规则枚举候选文件，计算数量与体积。绝不修改磁盘。
发现项 Finding一次扫描中某条规则命中的结果（文件数、体积、示例路径、阻塞原因）。
清理 Clean对选中发现项执行删除；默认先移入隔离区。
隔离区 Quarantine清理时文件先移到 Bytemop 管理的隔离目录，保留 N 天（默认 7 天，可设置）可一键还原，到期自动永久删除。
排除项 Exclusion用户指定“永不清理”的路径或规则，优先级高于任何规则。
阻塞 Blocked规则因某进程在运行（如浏览器）或权限不足而暂不可清理的状态。
干跑 Dry-run走完整清理流程但不落盘，输出“将会删除什么”，用于计划任务试运行和调试。
操作记录 History每次清理的不可变日志：时间、规则、数量、体积、结果，可追溯与还原。
计划任务 Schedule按周期自动扫描（可选自动清理“安全”级规则）。

4核心流程

F1 一键清理（主流程）

打开应用→概览页→点击“扫描”→扫描中（可取消）→结果列表→勾选/看明细→点击“清理”→确认对话框→清理中→结果页（释放 X，可撤销）
分支：无可清理内容 → “很干净”空状态｜有阻塞项 → 标注“请先关闭 Chrome”，该项不可勾选｜取消扫描 → 保留已扫描结果｜部分失败 → 结果页列出失败数与原因

F2 还原

历史与还原→选择某次清理→查看文件清单→还原全部 / 部分→原路径已有同名文件？另存为并提示→完成

F3 需要管理员权限的规则

扫描发现“Windows 临时文件”需提权→列表显示 🛡 标记→点击清理→UAC 弹窗（仅拉起助手）→拒绝 → 该项标记“未授权”，其余照常→助手完成后立即退出

F4 计划任务

设置 → 计划任务→选频率与规则范围→模式：仅扫描并通知 / 自动清理“安全”项→写入 Windows 任务计划→到点静默执行，写入历史

F5 首次启动

欢迎页（3 句话讲清“先预览、可撤销、零遥测”）→选语言/主题→是否启用计划任务（默认否）→进入概览

7规则与数据定义

规则是产品的“可信资产”。字段先定下来，后面所有模块共用。

规则 Schema（草案 v1）

{
  "id": "chrome.cache",                 // 全局唯一，小写+点
  "name": { "zh-CN": "Chrome 缓存", "en": "Chrome cache" },
  "description": { "zh-CN": "网页资源缓存，删除后会按需重新下载。" },
  "category": "browser",                // system | browser | app | dev | privacy
  "risk": "safe",                       // safe | caution | advanced
  "defaultSelected": true,
  "requiresAdmin": false,
  "blockedByProcesses": ["chrome.exe"],
  "minAgeHours": 0,
  "targets": [
    { "path": "%LOCALAPPDATA%\\Google\\Chrome\\User Data\\*\\Cache",
      "recurse": true, "include": ["*"], "exclude": [] }
  ],
  "action": "files",                    // files | recycle-bin | dns-cache | ...
  "since": "1.0.0"
}

关键约束

  • 路径安全：目标必须落在白名单根（%LOCALAPPDATA%、%TEMP% 等）之内且深度 ≥ 2；不跟随符号链接/junction。
  • 描述必填：没有“这是什么/为什么能删”的规则无法通过校验。
  • 风险等级决定默认行为：safe 默认勾选；caution 默认不勾并显示提示；advanced 默认隐藏。
  • 排除项优先于规则；禁用的规则不扫描。

本地数据

数据位置（%LOCALAPPDATA%\Bytemop，本机不漫游）说明
用户设置settings.json清理方式、保留天数、语言、外观、是否看过首次引导、计划任务；损坏时留 .bak
排除项 / 保持登录站点 / 卸载记录exclusions.json · privacy.json · apps.json各自独立；排除项和保持登录名单读不出来时一律停止操作（失败即关闭）
操作记录history.jsonl只追加，超过 2 MB 自动截短；导出功能尚未做
隔离区quarantine\<runId>\ 内含 meta.json + journal.jsonl + files\先写意图日志再移动，崩溃后可对账；还原绝不覆盖已有文件
规则包rules\*.json（内置副本在安装目录）签名文件 .sig
日志logs\*.log滚动 7 天，不含个人文件内容

8非功能需求

安全
  • 渲染进程无 Node 权限，仅通过受限 IPC 接口
  • IPC 只传规则 id，不传路径
  • 提权助手一次只做一件事，完成即退出
  • 安装包与规则包均签名
隐私
  • 默认零遥测、零账号
  • 文件清单只保存在本机
  • 崩溃报告发送前可预览
性能
  • 首次扫描 < 30 秒（SSD，常见规则集）
  • 扫描 CPU 低优先级，界面保持 60fps
  • 空闲内存 < 200 MB
体验与无障碍
  • 键盘全程可操作，焦点可见
  • 屏幕阅读器标注风险等级与状态
  • 中英文，布局不依赖文字长度
  • 深浅色，跟随系统

11实现偏离与新增决策

第 0–10 章是开发前的设计；下面记录实际做出来之后与设计不同的地方，以及开发中新定的决策。以本章为准。

与原设计的偏离

原设计实际原因
历史用 history.sqlitehistory.jsonl，只追加不引入原生依赖；日志只用于展示，写失败不影响已完成的操作
隔离区 manifest.jsonmeta.json（原子写）+ journal.jsonl（意图日志）崩溃恢复：日志先于移动，且只有隔离区里真有文件的行才算数
明细抽屉按子目录勾选、虚拟滚动按规则整体勾选；抽屉列出体积最大的 12 项，每项可“永不清理”排除项已覆盖“留下某些文件”的需求；10 万级文件的列表待做
启动项含计划任务/服务、启动影响、历史里可撤回只有注册表 Run 与启动文件夹；无影响评级；撤回只能在启动项页重新打开开关Windows 不公开启动影响数据，不自己估算
隐私：历史/Cookie，最近使用、剪贴板、DNS只做 Edge / Chrome / Brave 的历史、下载记录、Cookie；不支持 Firefox；清理不可还原，必须先关闭浏览器直接改浏览器的 SQLite 数据；不可还原所以每次确认，读不出保持登录名单则取消清理
磁盘分析：方块树图，重复文件只建议可钻取的条形列表 + 大文件 + 重复文件（大小 → 前 64 KB 哈希 → SHA-256）；删除走回收站，只能删最近一次分析列出的文件，每组重复至少保留一份回收站由 Windows 管理，比自建隔离区更直接；对没有回收站的盘或过大的文件会拒绝，避免被静默永久删除
应用：列表、体积、最后使用、卸载 + 残留列表、估算体积、卸载、残留；没有“最后使用”Windows 不提供可靠的最后使用时间
系统托盘未做；计划任务只发系统通知先保证后台任务可靠；托盘留到发布阶段
规则更新、签名、自定义规则编辑器、规则查看页规则只随程序内置，无更新和签名属于 v1.0 发布工作
设置里“开机自启”、清理“默认勾选”、最小文件年龄未做（最小文件年龄在规则里写死）暂无需求验证
隔离区超限时可选“改为永久删除”超限就停止并说明，让用户先清理或调大上限不静默降级；改成可选项留待以后
版本路线 v0.2 → v1.0实际按模块推进：M2、M7、M9、排除项、M4、M8、M3、M6、M5、首次引导按用户逐个点名的顺序

新增的决策

#议题决策
8管理员权限主程序永不以管理员运行。需要时才拉起一个短命的提权助手，经私有命名管道通信，带一次性令牌。任务只传规则编号、运行编号或应用名与残留编号，从不传路径；助手自己重新校验一切。
9删除失败即关闭读不出进程列表 → 当作浏览器在运行；读不出排除项 / 保持登录名单 → 停止操作；排除项永远优先于任何规则。
10卸载应用只启动程序自带的卸载向导，自己不删程序文件；商店应用通过 Windows 为当前用户移除。残留只按“文件夹名与应用名对得上”查找，通用名称、其他已安装应用的名称一律不认领，不碰注册表。
11残留去向用户目录下的残留进隔离区（可还原，遵循“清理方式”设置）。Program Files / ProgramData 里的残留需要管理员权限：交给助手，由助手自己找出并核对，拒绝 Windows 与 Microsoft 的文件夹、TrustedInstaller 所有的文件夹，然后移到回收站。设置和用户数据、共用位置默认不勾选。
12首次启动与外观三步欢迎页（语言与外观 → 安全原则 → 可选的每周扫描，默认关），可跳过，可在设置里重看。外观可选跟随系统 / 浅色 / 深色。
13计划任务只做“扫描并通知”或自动清理“安全”级规则；先改 Windows 任务，成功后才保存设置，两者不会不一致。
14发布方式不购买代码签名证书：发布未签名的版本，附 SHA-256 校验值；不做自动更新，只提示新版本。后果见发布清单 B 部分。

已知缺口

  • 提权助手产生的隔离记录与文件放在用户可写的文件夹里：已逐行校验日志并拒绝联接点，但没有根治。根治办法是安装版把它们放进 %ProgramData% 下仅管理员可写的文件夹，并对每个文件记录哈希。这也是助手“还原到 Program Files”目前没有开放的原因（所以机器级残留走回收站）。
  • 提权助手只在与调用方同一账号下运行；用另一个管理员的凭据确认 UAC 时会被拒绝并说明原因。
  • 改为永久删除、缩短隔离保留天数由主进程确认；OneDrive 目录里的文件不参与查重复（Node 读不到“仅在线”属性，所以整个目录跳过）。
  • 真实环境未验证：真实窗口的点击流程、Chrome / Brave、任务计划程序到点触发与通知、真实的卸载向导与 UAC、屏幕阅读器。
