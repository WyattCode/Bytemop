# Bytemop 发布前清单

状态：开发版 0.1.0，`npm start` 可运行，`npm test` 全部通过。已能打出未签名的便携版和安装包（见 B 部分），但安装包没有在真实系统里装过。
决定：**不购买代码签名证书**，发布的是未签名版本（见 B 部分）。
本清单只列“发布前必须做完或验证”的事，按优先级排。设计依据见 `product-design.html` 第 11 章。

## A. 必须在发布前解决（有安全或数据风险）

- [ ] **提权助手的数据放进受保护的文件夹。**
  现在助手写出的隔离记录和文件在 `%LOCALAPPDATA%\Bytemop`（用户可写）。安装版应改用 `%ProgramData%\Bytemop\elevated`，
  ACL：SYSTEM 和 Administrators 完全控制，Users 只读；日志里为每个文件记录 SHA-256，还原前核对。
  做完后才可以考虑开放“助手还原到 Program Files”。清单下面几项依赖它：
  - [ ] 提权运行记录的清除（到期、手动）要由助手执行，普通用户进程删不掉。
  - [ ] “历史与还原”里提权记录的还原继续走助手（已是如此）。
- [x] **渲染进程不能自己降低保护。** 改为永久删除、缩短隔离保留天数现在由主进程弹原生确认框（默认按钮是“取消”），
  拒绝时这两项保持原值、其余设置照常保存（`settings-guard.js`）。隔离上限调小不算降低保护，没有加确认。
- [x] **助手以另一个管理员账号提权时的处理。** `runElevated` 会在任务里带上调用方的用户目录，助手发现和自己的不一致就整个任务拒绝
  （`different-account`），界面给出说明。不再有“助手在别的账号下清理别人的数据”的情况。
- [x] **OneDrive“仅在线”文件。** 查重复时不再读取 OneDrive 目录里的文件（按 `OneDrive` / `OneDriveConsumer` / `OneDriveCommercial` 目录判断），
  界面提示跳过了几个。Node 读不到“仅在线”这个文件属性，所以是整个目录跳过，不是只跳过占位文件。

## B. 打包与分发（v1.0 的主体工作）

- [x] 打包工具：electron-builder（配置在 `package.json` 的 `build` 字段）。已能产出未签名的便携版和 NSIS 安装包：

  ```powershell
  npm test            # 先确认测试全过
  npm run dist        # 产出 dist\Bytemop-<版本>-portable.exe 和 dist\Bytemop-Setup-<版本>.exe
  npm run checksums   # 写出 dist\SHA256SUMS.txt，随安装包一起发布
  ```

  已验证：便携版 exe 能启动（`dist\win-unpacked` 也能）。**安装包本身没有在这台电脑上实际安装过**，安装、卸载、升级要在虚拟机里走一遍。
  **便携版不提供计划任务和管理员权限功能**：它每次启动都把自己解压到 `%TEMP%` 下的同一个文件夹，并且先删掉旧内容，
  所以计划任务或提权助手再启动同一个文件，会把正在打开的那一份的运行库删掉；而在用户可写的临时文件夹里提权运行也是提权漏洞。
  界面里这些功能会变灰并说明原因（`runtime.js`、`main.js` 里的 `portable`）。需要这些功能请用安装版。
- [x] **代码签名：决定不买。** 后果与对策：
  - Windows SmartScreen 会提示“已保护你的电脑”，用户要点“更多信息 → 仍要运行”；浏览器下载时也可能提示不常见。发布说明里写明这一步。
  - 提权助手的 UAC 弹窗会显示黄色的“未知发布者”。这是未签名的正常表现，不是故障；说明里写清楚，方便用户判断弹窗确实来自 Bytemop。
  - 杀毒软件可能误报（未签名 + 会删文件 + 会提权）。每次发布前用 Defender 扫一遍，必要时向微软提交误报。
  - 发布 SHA-256 校验值，让用户能核对下载的文件没被改过。
  - **不做自动更新**：没有签名的自动更新等于让下载通道成为攻击入口。改为设置里“查看新版本”只提示并打开下载页，由用户自己下载核对。
  - 以后想去掉这些提示，可以考虑 Azure Trusted Signing 之类按月付费的服务，或向开源项目的免费签名计划申请。
- [x] `app.setAppUserModelId('com.bytemop.app')` 已设置，且与 `appId` 相同，NSIS 安装包创建的开始菜单快捷方式会带这个 ID。便携版没有快捷方式，通知标题可能显示成 ID。
- [x] 计划任务：安装版指向安装目录里的 `Bytemop.exe`。卸载时删除 `\Bytemop\Scheduled Run`；**升级时保留**（`build/installer.nsh` 用 `isUpdated` 区分）。
  启动时如果设置是“开”而 Windows 里的任务已经不见了，会自动补回（只补缺失的，不改已有的）并记入历史。
- [ ] 安装程序卸载时：询问是否同时删除 `%LOCALAPPDATA%\Bytemop`（隔离区里可能还有用户可还原的文件，默认保留并提示）。
- [ ] ~~自动更新~~ 改为“检查新版本并提示”（不自动下载安装，见上面的签名决定）。
- [x] `asar` 已启用并开启完整性校验；Electron 保险丝已关掉 `RunAsNode`、`NODE_OPTIONS`、`--inspect`，并设为只从 asar 加载应用
  （防止写 `HKCU\Environment` 的程序借助用户点“是”的 UAC 弹窗以管理员身份执行代码）。安装版没有菜单，所以没有 DevTools 快捷键。语言包只带 en-US 和 zh-CN。
- [x] 图标：`build/icon.svg` 是源文件（深紫底块上的弧形擦痕），`build/icon.png` 是它的 512 像素导出，打包时转为 .ico；设置页有“关于”卡片（版本、数据文件夹、未签名说明）。
- [ ] 正式图标设计（现在是程序画的占位图标）、第三方许可证清单（Electron 的 `LICENSE.electron.txt` 和 `LICENSES.chromium.html` 已随包带上）。

## G. 第二轮审查（应用卸载、提权助手残留、首次引导、新界面）

三位独立审查员分别查了安全、逻辑与集成、界面与无障碍。已核实并修复的主要问题：

- **助手只信自己读到的东西**：残留的安装文件夹先解析成真实长路径（防 8.3 短名绕过深度、白名单和排除项）；
  不会碰其他已安装应用的安装文件夹，也不会碰包含它的上一级；机器级根目录改用 Windows 已知文件夹，不再读环境变量；
  “账号一致”检查在管道上改为强制；助手在移动前**自己弹确认框**，列出它将要移到回收站的确切路径（这是唯一可信的界面）。
- **便携版路径**：`PORTABLE_EXECUTABLE_FILE` 只有在进程确实从临时目录自解压运行时才采用，避免被持久环境变量劫持成“以管理员运行别的程序”。
- **残留判断**：隐藏的注册表条目（系统组件等）也算“还装着”，其文件夹归它所有；Bytemop 自己的数据文件夹不会被当成残留；
  “client”“server”等泛名不再被安装文件夹名带出；公共开始菜单快捷方式不再被一律拒绝；`msiexec /x {guid}` 这类无扩展名的卸载命令能识别。
- **界面**：应用列表“按大小/日期排序”未知值现在排在最后；设置页在欢迎页改动后会刷新，不再把旧值写回、也不会误关刚建的计划任务；
  窄窗口下清理页的按钮不再压住名称；欢迎页在最小窗口里不再被裁掉顶部；筛选、大小过滤、焦点、抽屉焦点陷阱、导航 `aria-current`、
  单选组方向键、若干状态播报和输入框名称都补上了。
- **卸载程序**：NSIS 卸载时会删除计划任务 `\Bytemop\Scheduled Run`（`build/installer.nsh`）。

仍然存在、需要知道的：

- 助手无法区分“真的卸载过”和“伪造的名称”：记录在用户可写的 `apps.json` 里。现在靠“助手自己的确认框 + 拒绝系统/共享/TrustedInstaller 文件夹 + 回收站可还原”兜底；
  不要在确认框里点“移到回收站”，除非列出的文件夹确实是你刚卸载的程序留下的。
- 云盘占位文件只对 OneDrive 做了跳过，Dropbox / iCloud 等没有。
- 从检查到移动之间仍有一个很短的窗口；移动前已重新检查一次，窗口缩小但没有消除。
- 升级前已有的 `settings.json` 没有“看过引导”标记，会再看到一次欢迎页。
- 圆环里“已用”和“可释放”两段主要靠色相区分，亮度对比不足；数值由文字表达，不影响读取。
- 仍未做：真实窗口、真实 UAC、真实安装包的验证（清单 D）。

## H. 第三轮审查（全部代码和界面）

四位审查员分别查了清理核心、隐私/磁盘/主进程、渲染进程、测试与打包。已核实并修复：

- **会删到用户想保留的文件**
  - 排除项和 8.3 短路径：TEMP 是短名时，排除项形同虚设。现在清理根目录先转成真实长路径，排除项也同时登记短名和长名。
  - “最小文件年龄”只看修改时间：刚解压出来、保留旧时间戳的文件会被当成旧文件。现在取“修改时间”和“创建时间”里较新的。
  - 空文件夹清理不看年龄：应用刚建的空文件夹会被删。现在同样看年龄。
  - TEMP 变量指向用户目录或“文档”时，“清理临时文件”会变成清理整个用户目录。现在这类根目录被拒绝。
  - 排除项里无法解析的 `%变量%` 被悄悄丢掉（等于取消保护）。现在原样保留。
  - `**\` 现在可以匹配零层文件夹（`Downloads\**\*.iso` 也覆盖 `Downloads\x.iso`）。
  - 便携版运行库在 TEMP 里：不再被“用户临时文件”规则当成垃圾。
- **隔离区**：meta 并发写入互相覆盖（现在逐个排队 + 唯一临时名 + 瞬时错误重试 + fsync）；meta 损坏时整次清理“消失”（现在从日志重建）；
  还原可能覆盖期间新建的文件（现在用硬链接保证不覆盖）；跨盘复制中途崩溃留下被当成完好的残缺文件（现在先写 `.part`）；
  刚创建的运行目录可能被另一进程的恢复清掉（现在有年龄保护）；上限检查把被浏览器占用、根本不会移动的规则也算进去。
- **设置**：读取时遇到杀毒软件占用等临时错误，会当成损坏、用默认值覆盖真实设置。现在只显示默认值，不写回。
- **时钟**：时钟跳到未来会让整个隔离区在启动时“到期”被清空。现在时钟明显异常时跳过到期清理（连续两次启动都认可才接受长时间未用）。
- **提权**：UAC 取消只认英文文案，中文系统会被当成“失败”（现在认 Win32 错误 1223）；管道上收到 `null` 会让主进程抛异常；第二个带令牌的连接也能拿到任务（现在只给第一个）；
  参数引号处理在末尾反斜杠时出错（统一用标准 Windows 引号规则）。
- **打包**：升级时安装程序的卸载宏会删掉计划任务（现在升级保留）；便携版的计划任务/提权会让正在运行的实例被删（现在在便携版里关闭）；
  可执行文件的保险丝（见上）；`electron` 版本固定为精确值；`engines` 写明 Node ≥ 22.5。
- **隐私**：保留“mail.google.com”现在也保留 `.google.com` 的登录 Cookie；公共后缀（`github.io`、`co.uk`）不能当“网站”加入保留名单，`foo.github.io` 被当成独立网站；
  浏览器数据库的临时副本在启动时清扫；“浏览历史”同时清掉 Favicons。
- **磁盘**：硬链接同一个文件被重复统计、被列成“重复文件”（现在按 dev:ino 去重）；超过 64 层的文件夹被悄悄忽略（现在计入“无法访问”）；
  丢进回收站前再核对修改时间；空路径不再变成“当前目录”；盘符列表来自 Windows 的固定磁盘列表，不再逐个探测盘符（避免卡住线程池）；
  回收站检查现在会排除设置了“不移到回收站”的磁盘（否则 `trashItem` 会静默永久删除）。
- **主进程**：IPC 只接受自己页面的调用；禁止弹窗和页面跳转；拒绝所有权限请求；安装版去掉菜单（没有 DevTools 快捷键）；
  窗口先显示，再做隔离区恢复和到期清理；未处理的启动错误会弹窗并退出，不再留下看不见的进程。
- **界面**：清理成功后重新扫描失败，不再用错误提示盖掉成功信息；“上次清理”现在也算应用残留清理；“全部干净”在管理员项未扫描时不再这么说；
  成功信息自动滚动到可见处；磁盘删除不再能连点两次；选文件夹不再取消正在进行的分析；计划任务连改两项不再丢第二项；启动项页面失败/空筛选状态；
  错误文案不再套两层前缀；输入法回车上屏不再误触发添加；一批没有错误处理的按钮；大数字 `100.0 KB` 改为 `100 KB`；英文单数；
  排除项文件损坏时给出“备份并重置”的出口；清理了未使用的文案、样式；长列表行用 `content-visibility`。
- **测试**：真实系统测试（真的建任务、写注册表）改为设置 `BYTEMOP_REAL_TESTS=1` 才运行（`npm run test:real`）；
  `npm run test:clean` 清理测试留下的临时文件夹（本次清掉了 5085 个）；新增 20 多条回归测试（共 240 条，其中 2 条真实系统测试默认跳过）。

仍然存在：

- 浏览器数据库的读写是同步的，大历史文件会让界面卡几秒（需要放进 worker 线程）。
- 提权助手的数据放在用户可写文件夹里（见 A 第一项）。
- 测试大多只在 Windows 上能跑；没有 CI。
- 清理 `privacy:clean` 的“不可还原”确认只在界面层。
- 通知阈值：计划扫描发现任意大小都会弹通知（没有“至少 N MB”的门槛）。
- 真实窗口、真实 UAC、真实安装包、屏幕阅读器的验证仍需手动（清单 D）。

## I. 真实窗口自检（`npm run selftest`）

`selftest.js` 在开发模式下驱动**真实的窗口**（真实的 preload、真实的 IPC、真实的服务），只做只读调用，并保存每一页的截图：

```powershell
$env:BYTEMOP_SELFTEST_DIR = "$env:TEMP\bytemop-shots"; npm run selftest
```
